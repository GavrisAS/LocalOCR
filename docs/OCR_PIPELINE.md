# OCR pipeline

1. Проверка размера/формата/числа кадров, EXIF transpose, RGB, deskew до 8°.
2. Морфологические горизонтальные/вертикальные линии; связанные контуры таблиц.
3. OCR table region, Table Recognition:, stream=false, temperature=0, seed=0,
   num_ctx=32768, num_predict=16000 (настраивается через Settings).
   Для геометрически отдельной таблицы stop=</table> прекращает повторную
   генерацию; отброшенный API closing delimiter возвращается только после
   done_reason=stop. Незакрытые строки/ячейки parser всё равно отклоняет.
4. Строгий инертный parser: tr/th/td, thead/tbody/tfoot, spans, br, Unicode.
5. Координатная сетка с проверкой overlaps, holes, bounds, limit.
6. Сравнение числа строк/столбцов с геометрией, даже при корректном HTML.
7. При mismatch/усечении: автоматические границы строк, фрагменты до 1000 px,
   одна строка overlap, две OCR-попытки на фрагмент, затем геометрическое
   деление проблемного диапазона (не более 5 уровней, 96 запросов на таблицу).
8. Сборка только по абсолютному индексу геометрической строки/столбца.
   В overlap сверяются все значения и spans. Текстовый конфликт проверяется
   двумя локальными OCR-запросами. При подтверждении используется подтверждённое
   наблюдение, иначе сохраняется первое исходное OCR-наблюдение; альтернативы
   и неопределённость явно показаны в REVIEW. Конфликт spans — FAILED.
9. Данные и formatting → openpyxl → атомарный XLSX + локальный отчёт.

Для изображений без уверенной линейной геометрии полнота не доказана — REVIEW.
Для объединений на границах фрагментов нет спекулятивного восстановления:
несогласованные spans приводят к FAILED. Текстовые повторы не удаляются по
значению/номеру: одинаковые реальные строки сохраняются.
Длинные таблицы обрабатываются сразу фрагментами. Нет source-specific crops.
Структурная точность и текстовая точность различаются: совпавшая сетка не
доказывает правильность текста. Никаких автоматических 0/О, 1/I, С/C исправлений.
